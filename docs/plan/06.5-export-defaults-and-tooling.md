
### 6.5.6 Image replication for non-standard model sizes

COCO val2017 images are typically ~640x480. For models with larger input sizes (e.g. 960x608), upscaling small images degrades quality and benchmark validity. Instead, replicate (tile) images to fill the target resolution.

**Create:** `scripts/replicate_images.py` (standalone script, not a CLI tool)

**Behavior:**
- Accept: `--input-dir`, `--output-dir`, `--target-width`, `--target-height`
- For each image in input-dir:
  - Read image dimensions (H, W)
  - Compute repeat factors: `nx = ceil(target_width / W)`, `ny = ceil(target_height / H)`
  - Tile image `nx * ny` times using `numpy.tile(img, (ny, nx, 1))`
  - Do NOT crop — let the preprocessing pipeline (letterboxing) handle the final resize
  - Save to output-dir with same filename
- Use tqdm for progress

**Example usage:**
```bash
python scripts/replicate_images.py \
  --input-dir e2e_results/coco_val2017 \
  --output-dir e2e_results/coco_960x608 \
  --target-width 960 --target-height 608
```

**Why not just letterbox?** Letterboxing upscales a 640x480 image to 960x608 by padding — this means Triton processes mostly blank pixels, which doesn't reflect real workload. Tiling creates a full-resolution image that exercises the full inference pipeline at native resolution, producing meaningful benchmarks and realistic drift measurements.
